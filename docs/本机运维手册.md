# 本机运维手册

## 本机现状与权限

正式地址 http://127.0.0.1:3000，预发布3003，开发web5173/API3001；PostgreSQL17项目集群55432，仅127.0.0.1。正式库aiwb_production，预发布aiwb_stage；开发aiwb_dev、可清理测试aiwb_test。集成测试只允许独立本机*_test库。

正式应用以独立受限PG角色运行，无超级用户/建库/建角色权限；迁移角色单独保管。当前Windows用户负责运维，不是独立OS服务账号。PUBLIC_ORIGIN固定127.0.0.1，本机HTTP Cookie为HttpOnly/Lax；不要直接开放局域网或公网。需要公网时另配HTTPS、网络隔离和服务账号。

敏感文件：`.env`是本机管理/开发/测试连接；`.data/runtime/<环境>/config.json`是该环境独立应用与迁移连接；`credentials.txt`是初始Owner随机密码；`.data/backup-keys/<环境>.key`是备份密钥。这些文件有当前用户/SYSTEM ACL，不进普通FS快照，不发到聊天。管理默认口令已随机轮换，旧口令已拒绝。管理员恢复账号是CLI操作，不提供默认通用密码。

## 已部署环境的日常命令

在项目根目录、PowerShell7执行：

```powershell
pwsh -NoProfile -File scripts/local-workbench.ps1 start
pwsh -NoProfile -File scripts/local-workbench.ps1 status
pwsh -NoProfile -File scripts/local-workbench.ps1 backup
pwsh -NoProfile -File scripts/local-workbench.ps1 stop
```

start幂等启动已有正式版本和巡检。stop停止应用与巡检，保留共享PG集群。电脑重启后再start；观察会如实记录中断。服务启动不会自动迁移，不自动导入演示数据。已有部署不重新执行init或seed。整集群reset被禁止；不要删除pgdata。

底层命令：`node scripts/native.mjs status|smoke|stop production`；`start production local-final-v5`仅用于明确版本启动。start前逐文件核验运行包，stop核对PID入口与启动时间，拒绝误杀复用PID。

## 新环境准备（不覆盖既有数据）

本轮固定Windows x64、Node22.23.4、pnpm11.25.0、PowerShell7、PostgreSQL17.11。PG_BIN可指向本机PG17的bin目录，PNPM_STORE_DIR可指定pnpm存储；当前分别为E:/tools/PostgreSQL/17/bin与D:/.pnpm-store。不要把可执行依赖目录当作数据库数据目录。

```powershell
pnpm install --frozen-lockfile --prod=false --store-dir D:\.pnpm-store
node scripts/setup-local-env.mjs
pwsh -NoProfile -File scripts/dev-db.ps1 init
pnpm db:generate
pnpm verify
$releaseId='local-20261105-02'
node scripts/local-ci.mjs .data/release-check --release=$releaseId
```

setup-local-env只在.env不存在时生成随机口令并设置ACL；拒绝覆盖。init新建项目内独立数据目录，从初始化起使用SCRAM；不临时切到trust。默认55432，端口已有其他实例则拒绝接管；数据目录必须在本项目.data内。已有集群先start，init只核对数据目录、认证与开发/测试库。中文Windows路径以实际字节核对，不将编码差异当成授权目录。

同机全新55433测试集群的创建、认证、开发/测试库建立及停止已验收；这不等于另一台干净主机实测。参数例：`-Port 55433 -DataSubdirectory .data/pgdata-init-acceptance`。不要在实际部署中随意更改已有实例端口或目录。

初始化正式环境：先`node scripts/native.mjs init production`，备份空库，再`migrate production <候选>`、`bootstrap production <候选>`。bootstrap从受限随机密码初始化唯一Owner，不重复建第二个Owner。第一次部署后密码只在credentials.txt；已存在Owner不会覆盖原密码。

## 流水线与发布

local-ci按顺序执行工具链、历史迁移hash、类型/lint/单元/构建、独立空库和非空升级、26个真实DB套件、源码密钥扫描、生产依赖审计，然后生成不可覆盖的新运行包、CycloneDX清单与candidate.json。任一失败不生成候选。工具和pnpm存储访问需当前Windows用户权限；不要关闭供应链检查来掩盖缓存问题。

运行包位于`.data/releases/<版本>`，包含编译API、正式web、固定生产依赖、schema/migrations、SBOM、SHA256清单。链接必须留在包内，不挂工作区源码。打包后会重新以frozen-lockfile/prod=false同步工作区依赖。

```powershell
$releaseId='local-20261105-02' # 使用上一步已验收的新包
node scripts/release.mjs deploy stage $releaseId
node scripts/native.mjs smoke stage
node scripts/release.mjs deploy production $releaseId
node scripts/native.mjs smoke production
```

部署先核验并备份，迁移用运行包冻结文件，然后启停、冒烟、记录历史。当前正式为local-final-v5。不要随意重跑production-check，它会创建合成记录再移入回收站，适用于明确的发布验收。

## 备份与恢复

```powershell
node scripts/backup.mjs create production
node scripts/backup.mjs retention production
node scripts/backup.mjs restore production <备份ID> aiwb_restore_标识_test
```

create使用一致快照的PG自定义dump，通过管道AES256GCM加密；元数据带版本、24表数量/指纹、密文大小/hash，元数据也参与GCM认证。备份在`.data/backups/<环境>`，密钥在另一个受限目录。密钥丢失无法恢复，项目所有者必须单独妥善保管。

restore先校验hash/大小及完整GCM认证，再新建隔离库；拒绝正式库或已有目标。临时明文只在受限runtime里，finally清理。恢复数据库由迁移角色拥有，再授予应用表/序列权限。源库不会被覆盖。真实恢复已核对24表、修订、usage、关联、Owner登录和API；实测小夹具约0.4秒的数据库恢复不外推大库。

每日备份由巡检在23小时后触发；失败15分钟后重试。保留14个日点、8个周点、12个月点，并保留最近10次发布回退备份及retention-pins.json固定点。retention默认仅报告，--apply才清理已验证的过期文件；损坏记录单独报告。发布/演练引用的固定点不要解除后立即删除。

恢复提升为正式库前：停止应用和巡检（停写）→备份当前库并复制受限config→恢复新隔离库→验证结构/表指纹/账号/权限→明确恢复点之后差异→将恢复库改为非_test名称→撤销旧会话、令旧临时传输过期、重授角色→确认后切换配置并启动。保留原库与当前完整备份供差异导出合并。临时传输文件不在dump内，旧下载需重新导出，未完成导入要重新上传。

本机PGdump不包含操作系统角色或整机配置；初始化脚本负责角色/ACL重建。业务JSON导出不替代数据库备份。同机副本不能抵御整盘损坏，异机灾备尚未执行。

## 代码回退和故障响应

`node scripts/release.mjs rollback production <旧版本>`先保存当前完整备份；只回退应用代码，不自动执行down迁移。目标包未声明当前已应用迁移时拒绝自动回退，先审查兼容性。本轮5个现有迁移及附加表探针下的新旧版本回退已实测，不保证任意未来破坏性迁移都能降级。

配置、release-history、备份引用在runtime。API不可用先查health、PG状态和结构化日志requestId；磁盘低于20%警告、10%拒绝大传输；备份失败保留上次有效恢复点；队列超过10分钟/运行超过20分钟检查worker租约。未知写入只查原键或重试原提交，不换键重复创建。严禁直接删pgdata或将数据库恢复当作代码复制。

## 日志、告警和观察

- api-events.log：结构化访问日志，20MiB轮转、10份历史；不记录正文、Cookie、密码。
- api-时间.log/error.log：启动期stdout/stderr；排障后由所有者按保留需要整理，不能删除当前运行文件。
- alerts.jsonl：本机告警与恢复通知，重复故障去重；没有外部邮件/聊天发送。
- monitor-state.json、health.jsonl：当前状态和实际60秒采样。
- observation.json：样本数、失败/告警、最大间隔和30分钟/24小时覆盖。
- observation-24h.json：到期自动生成；有间断/故障则needs_review，不能提前填passed。

项目所有者负责查看本机状态并响应告警。进程或整机停止时无法自我通知，外部监控属于扩展。每月用新隔离库做一次恢复验证；每次版本升级后检查回退备份。24小时运行观察按用户确认独立于开发技术交付，最终以后台真实记录为准。
