# 数据库实现约定（F03 冻结）

> 日期：2026-11-03｜配套：[数据库与接口设计](../../全栈开发任务/数据库与接口设计.md)（逻辑设计）、[OpenAPI](api/openapi.yaml)（契约）、[ADR-0004](adr/0004-条件写幂等与事务边界.md)
> 本文只冻结**实现层选择**（类型、命名、约束落法），不重复逻辑设计。F05 依此产出 Prisma schema 与审核 SQL 迁移。

## 1. 标识与时间

| 项 | 约定 | 理由 |
|---|---|---|
| 主键 | `uuid`，默认 `gen_random_uuid()`（PG 17 内置） | 服务端生成；离线新建接受客户端 UUID v4（格式校验） |
| 时间戳 | `timestamptz(3)`，默认 `now()` | UTC 存储，毫秒精度足够 |
| 业务日期 | `date` | 避免时区偏移（ADR-0005） |
| 版本 | `integer not null default 1` | 条件写（ADR-0004） |
| 软删除 | `deleted_at timestamptz null` | 回收站 30 天 |
| 来源元信息 | `jsonb null` | 旧数据导入，不参与授权 |

补充列（F03 契约冻结 C-04，为满足 API 的 `createdAt`／`updatedAt`）：`workspace_members.updated_at`、`tags.created_at`、`workspace_invites.created_at`、`entry_usage.created_at`。`entry_revisions.saved_at` 直接作为 `createdAt`，`audit_events.at` 作为 `createdAt`（审计不可变，无 `updatedAt`）。不为了契约好看而新增无业务意义的列。

## 2. 命名与映射

- 数据库：`snake_case` 表名与列名（`workspace_members`、`created_at`、`done_at`）。
- Prisma：模型用 `PascalCase`，字段用 `camelCase`，逐模型 `@@map`／逐字段 `@map`，**不开启** Prisma 的隐式命名转换，避免多一层魔法。
- 枚举：使用 PostgreSQL 原生 `enum`（`task_priority`、`task_status`、`entry_type`、`entry_status`、`member_role`、`member_status`、`project_stage`、`job_state`、`job_type`、`transfer_type`）。新增值用 `ALTER TYPE ... ADD VALUE`；删除值必须重建类型（需单独迁移与回填）。
- 枚举值统一小写：`p0|p1|p2`、`todo|doing|done`、`note|design|adr|troubleshoot|command`、`draft|verified|archived`、`owner|editor|viewer`、`planning|developing|paused|done`（`project_stage`，F03 冻结；设计文档未列具体取值，此处补定并同步到 OpenAPI）。
- `tool`、`scene`、`lang` 为受限文本（`varchar(32)`，非空，去首尾空白），不做原生枚举：工具与场景随实践变化，用 DTO 长度校验避免频繁改类型。
- 项目进度模式用布尔 `progress_manual`，不建枚举：`false` 表示按任务计算，`true` 时 `manual_progress` 生效（0 是合法值）。

## 3. 空间边界

每个业务表除 `id` 主键外增加 `UNIQUE (workspace_id, id)`，供复合外键使用：

```sql
ALTER TABLE tasks ADD CONSTRAINT tasks_ws_id_key UNIQUE (workspace_id, id);
ALTER TABLE task_entries ADD CONSTRAINT task_entries_task_fk
  FOREIGN KEY (workspace_id, task_id) REFERENCES tasks (workspace_id, id);
```

涉及复合外键的表：`task_entries`、`entry_tags`、`entries(project_id)`、`tasks(project_id)`、`ledger_records(project_id)`、`ledger_records(entry_id)`、`entry_revisions(entry_id)`、`entry_usage(entry_id)`。Prisma schema 无法表达的复合外键写入**审核 SQL 迁移**（`database/prisma/migrations/*/manual.sql` 由迁移脚本拼接执行）。

## 4. 约束落法

| 规则 | 落点 | 实现 |
|---|---|---|
| 标题 1～200 字、摘要 ≤300 字、下一步 ≤300 字 | DB + DTO | `char_length()` CHECK |
| 正文 ≤20480 UTF-8 字节 | DB + DTO | `octet_length(body) <= 20480` |
| `minutes > 0`、`saved_minutes >= 0`、`effect between 1 and 5` | DB + DTO | CHECK |
| `manual_progress between 0 and 100` | DB + DTO | CHECK |
| `done` 与 `done_at` 一致 | DB + Service | `CHECK ((status = 'done') = (done_at IS NOT NULL))` |
| 邮箱规范化唯一 | DB | `email_normalized` 唯一；规范化在应用层（小写 + trim），不用 `citext` |
| 标签同空间唯一 | DB | `UNIQUE (workspace_id, name_normalized)` |
| 每条目 ≤20 标签 | Service | 事务内计数，超限 422 |
| 至少一位 Owner | Service | `SELECT … FOR UPDATE` 锁成员集合后校验（不写触发器，便于审计与错误文案） |
| 每 entry ≤5 修订 | Service | 事务内插入后裁剪 |
| 幂等唯一 | DB | `UNIQUE (user_id, workspace_id, scope, key)` |
| 导入映射唯一 | DB | `UNIQUE (workspace_id, source_namespace, entity_type, legacy_id)` |

## 5. 索引

按逻辑设计第 3.1 节逐条落地，另加：

```sql
-- 稳定分页（每张核心表）
CREATE INDEX tasks_ws_updated_idx ON tasks (workspace_id, updated_at DESC, id DESC) WHERE deleted_at IS NULL;
-- 紧急聚合
CREATE INDEX tasks_ws_status_due_idx ON tasks (workspace_id, status, due_date, id) WHERE deleted_at IS NULL;
-- 日志时间线
CREATE INDEX dev_logs_ws_date_idx ON development_logs (workspace_id, log_date DESC, created_at DESC, id);
-- 搜索候选（先缩小空间与状态）
CREATE INDEX entries_ws_status_type_idx ON entries (workspace_id, status, entry_type, updated_at DESC, id) WHERE deleted_at IS NULL;
-- 台账统计
CREATE INDEX ledger_ws_date_scene_idx ON ledger_records (workspace_id, record_date, scene);
-- 作业领取
CREATE INDEX jobs_state_lease_idx ON transfer_jobs (state, lease_until, created_at);
```

`pg_trgm` 本期**不建**；两字中文词性能在 F22 用 `EXPLAIN ANALYZE` 实测后再决定（写入 FS022）。

## 6. 查询约定

- 所有 Repository 方法第一个参数为 `workspaceId`，并拼入 `WHERE workspace_id = $1`；禁止 `findUnique({ id })` 形式。
- 列表默认 `limit=20`、最大 `100`；排序必须含 `id` 作为最后一级以保证稳定分页。
- 搜索：`ILIKE '%' || escaped || '%'`，先转义 `%`、`_`、`\`；仅查 `deleted_at IS NULL`。
- 统计聚合在 SQL 内完成（`GROUP BY date_trunc`／按 `record_date` 分组），不把整表读到 Node。
- 事务使用 Prisma `$transaction(async (tx) => …)` 交互式事务；事务内不发起 HTTP 调用、不做文件 IO。

## 7. 迁移纪律

1. 所有结构变更生成迁移文件，**不手工改生产库**。
2. 迁移分两步：`expand`（加列／加表，兼容旧代码）与 `contract`（删列，下一版本）。
3. 复合约束、CHECK、部分索引、原生枚举变更写在同一次迁移的 `manual.sql` 中，保证空库与升级库结果一致。
4. 每个迁移必须有：空库执行通过、已有数据升级通过、回滚策略说明（F05 的 fixture 覆盖）。
5. 应用启动**不**执行迁移（ADR-0004 与 F44 的独立迁移 job）。

## 8. 待 F05 验证的实现风险

| 风险 | 验证方式 |
|---|---|
| Prisma 7 的 driver adapter 与 `prisma-client` 生成器初始化方式 | 在 F05 跑通 `migrate dev` + 一次真实读写后再定稿脚手架 |
| 原生枚举与 Prisma 双向映射 | 生成 client 后检查类型与 `enum` 值一致 |
| 复合外键在 Prisma migrate 中的保留情况 | 迁移后 `psql \d+` 核对约束存在 |
| `gen_random_uuid()` 在 PG 17 无需扩展 | 空库执行 `SELECT gen_random_uuid()` |
