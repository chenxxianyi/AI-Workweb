# 契约冻结决定（F03）

> 日期：2026-11-03｜对应：[OpenAPI 草案](openapi.yaml)、[数据库与接口设计](../../全栈开发任务/数据库与接口设计.md)、[错误码](错误码.md)
> 编写契约时发现 12 处“设计文档未给具体取值或与通用句式有范围差”的地方。本文逐条冻结决定，**不修改**设计文档的语义，只补足实现所需细节。后续实现以本文件 + OpenAPI 为准；如需推翻，先改本文并记变更。

## 1. 取值冻结

| 编号 | 项 | 决定 | 说明 |
|---|---|---|---|
| C-01 | `project.stage` | `planning` / `developing` / `paused` / `done` | 设计文档只写“固定枚举”；四值覆盖项目雷达的阶段展示与归档语义（归档用 `deleted_at`/`archived` 标志区分，不复用 stage） |
| C-02 | 知识五类型 | `note`（笔记）/ `design`（方案）/ `adr`（架构决策）/ `troubleshoot`（排障）/ `command`（命令） | 与需求 R10“五类型”一一对应；中文标签在前端映射，数据库存英文枚举 |
| C-09 | 回收站类型 | `project` / `task` / `entry` / `log` / `ledger` | 与五类软删除实体的路由 `{type}` 一致；`workspace` 本身不进回收站 |
| C-10 | 路径参数名 | 统一用 `{id}` | 成员与使用统计无独立主键时，`id` 取 `userId` / `entryId`，在 schema description 标注 |

## 2. 端点补充

| 编号 | 项 | 决定 | 理由 |
|---|---|---|---|
| C-03 | `GET /workspaces/{w}/logs/{id}` | **采纳**，进入契约 | 没有详情端点就取不到当前 `version`／`ETag`，日志的条件写无法实现；第 5 节表的“CRUD”语义本就包含单条读取 |
| C-08 | 导出／导入为异步 | `POST /exports`、`POST /imports/preview`、`POST /imports/{jobId}/commit` 返回 `202 + TransferJob`，经 `GET /transfers/{jobId}` 轮询；导入预览挂在 job 的 `preview` 字段 | 与第 7.3 节状态机一致；不新增第 5 节之外的路径 |
| C-11 | `includeDeleted` | 仅 `tasks`、`entries` 列表支持；`true` 需 owner/editor | 设计只说默认排除软删除；限定范围避免每个列表都开探测口 |
| C-12 | `bootstrap-owner` | 服务器 CLI，不进 HTTP paths | 方案第 7 节与第 5 节均明确不是公开接口 |

## 3. 字段与版本策略

| 编号 | 项 | 决定 |
|---|---|---|
| C-04 | 缺少 `created_at`／`updated_at` 的表 | **加列**：`workspace_members.updated_at`（`joined_at` 作 `createdAt`）、`tags.created_at`、`invitations.created_at`、`entry_usage.created_at`；`entry_revisions.saved_at` 作 `createdAt`（不加冗余列）；`audit_events.at` 作 `createdAt`（不可变，无 `updatedAt`）。契约统一暴露 `createdAt`／`updatedAt`，映射关系在 OpenAPI description 中写明 |
| C-05 | 无 `version` 的实体（`User`、`Session`、`Invitation`、`Tag`、`EntryRevision`、`EntryUsage`、`AuditEvent`） | **不加 `version`**：这些实体要么不可编辑（审计、修订、使用统计），要么以自然键 + 幂等键控制（会话吊销、邀请撤销、标签唯一约束）。§4“PATCH/DELETE 使用 If-Match”只适用于带 `version` 的可编辑实体，实现时按实体类型分派 |
| C-06 | `ErrorResponse` 扩展 | 允许可选 `error.currentVersion`（412/409 供刷新重试）与 `error.details`（如 `planHash`、`jobId`）；基础结构 `{error:{code,message,fieldErrors?},requestId}` 不变，`错误码.md` 为权威 |
| C-07 | 认证响应体 | `GET /auth/csrf` → `{csrfToken, expiresAt}`；`POST /auth/login`、`POST /auth/invitations/accept` → `{user, memberships, csrfToken, sessionExpiresAt}`（登录轮换会话后必须换 CSRF）；`GET /auth/me` → `{user, memberships, preferences}` |
| C-13 | 分页元信息 | 统一 `meta: { nextCursor, hasMore }`；`cursor` 绑定空间、排序与筛选指纹，改变筛选即丢弃 |

## 3.1 限流（C-14，F08 补充）

| 接口 | 窗口内上限 | 实现 |
|---|---|---|
| `POST /auth/recovery/complete` | 5 次 / 60 秒（按 IP + 方法 + 路径） | `@RateLimit({ limit: 5, ttlMs: 60_000 })` |
| `PATCH /auth/password` | 10 次 / 60 秒 | `@RateLimit({ limit: 10, ttlMs: 60_000 })` |
| `POST /auth/login`（F09） | 默认 10 次 / 60 秒，另按账号计数 | F09 实现 |
| 其他接口 | 不设默认全局限流 | 需要时按接口显式加 |

超限返回 `429 RATE_LIMITED`，`error.details.retryAfterSeconds` 给出建议等待秒数。
计数在进程内，多实例部署不共享（本期单机部署可接受，F43 按部署形态复核）。

## 3.2 会话与 CSRF 落地细节（C-15，F09 补充）

| 项 | 决定 |
|---|---|
| Cookie 名 | 会话 `sfs_session`（`HttpOnly`、`SameSite=Lax`、`Path=/`，HTTPS 加 `Secure`）；CSRF `sfs_csrf`（**非** HttpOnly，供前端读取） |
| 会话令牌 | 32 字节随机 base64url；数据库只存 SHA-256；空闲 24h、绝对 7 天；每 60 秒最多续期一次 |
| 登录轮换 | 每次登录新建会话（多设备并存），并轮换 CSRF 令牌；旧 CSRF Cookie 被覆盖 |
| CSRF 校验 | 已登录：`X-CSRF-Token` 的 SHA-256 等于会话 `csrf_token_hash`；未登录（登录）：双提交（头 == `sfs_csrf` Cookie） |
| 来源校验 | 只要请求带 `Origin`／`Referer`，就必须与 `PUBLIC_ORIGIN` 同源；两者都没有时放行（curl/测试），仍受 CSRF 令牌约束 |
| 豁免 | `@CsrfExempt()`：`POST /auth/recovery/complete`（持有型一次性令牌，非 Cookie 凭据） |
| 默认鉴权 | 全局 `SessionAuthGuard`：除 `@Public()`（health、`GET /auth/csrf`、`POST /auth/login`、`POST /auth/recovery/complete`、`GET /auth/csrf-cookie-name`）外都需登录 |
| 登录锁定 | 15 分钟内失败 5 次 → `429 RATE_LIMITED`（`details.retryAfterSeconds`），成功登录清零；按账号计数，进程内 |
| 会话管理 | `GET /auth/sessions`（自己全部有效会话，标记 current）、`DELETE /auth/sessions/{id}`（非本人 404）、`DELETE /auth/sessions`（吊销其他设备） |
| 重启 | 会话存数据库，进程重启不影响已登录设备；`SessionAuthGuard` 每次请求查库 |

## 4. 契约检查计划（F44 落地）

1. CI 用 `openapi-spec-validator` 校验语法（注意：本机 Python 3.12.0b1 需 PyYAML ≥ 6.0.2，否则 C 扩展崩溃）。
2. 从 OpenAPI 生成前端类型（`packages/contracts`），与手写 DTO 比对，差异即失败。
3. 破坏性差异（删除路径、删除必填字段、收紧枚举）需新增 ADR + 版本号提升（`0.1.0` → `0.2.0`）。

## 5. 与设计文档的关系

- 本文件只补足细节，**不改变**实体语义、权限矩阵、事务边界与删除规则。
- 若未来实现发现必须改变语义，按 F01 第 6 节流程：先改设计文档与本文 → 再改 OpenAPI → 再改实现与测试 → 记入 FS 记录。
