# 业务传输作业

POST `/api/v1/workspaces/{workspaceId}/exports`：`{format:"json"|"markdown",schemaVersion?:2,includeTrash?:false}`，CSRF及Idempotency-Key，返回202持久job。Editor/Owner可创建，含回收站仅Owner。
GET `/transfers/{jobId}`查询状态；GET `/transfers/{jobId}/download`认证流式下载。均限定当前空间，创建者或Owner；其他成员即使猜到ID也404。下载仅在succeeded且24小时内，响应no-store和安全附件名，内部目录不作为静态目录公开。

进程内worker轮询数据库，状态与60秒租约CAS领取，每250条续租；REPEATABLE READ事务分批读取全部业务与关系，流式写随机`.part`，fsync并原子改名后才标成功。进程崩溃后过期租约重领，最多3次；旧持有者不能提交。24小时过期结果及孤立part清理。文件SHA256保存到job。
JSON schemaVersion=2仅业务字段，来源namespace、空间时区、关系、最近5条修订和usage，不含账号/会话/邀请/密码/角色。软删除父对象不在包内时将该关联置空；Markdown元信息用JSON编码，避免标题换行造成YAML注入。

运行文件默认位于`TRANSFER_STORAGE_DIR=.data/transfers`，本机API从仓库根启动。测试使用独立`.data/transfers-test`，不进入普通存档。业务导出方便迁移，不替代数据库备份。

导入预览：POST `/imports/preview?sourceNamespace=来源标识`，CSRF+Idempotency-Key，Content-Type为`application/octet-stream`，请求体直接是JSON文件字节（与普通128KiB JSON请求限制分开）。文件按流落内部目录，最多512MiB；流式解析逐实体暂存，最多25万实体、25万关系，危险键、重复来源ID、过深结构和非法字段拒绝。返回202的job（正常已preview_ready；进程中断的uploaded/validating由worker租约恢复）。GET `/imports/{jobId}/items?cursor=...`分页查看计划；GET `/transfers/{jobId}`返回计数、planHash、失败码，失败校验报告放counts.validationError。

旧文件`schema=1`需要显式namespace；新文件`schemaVersion=2`可使用包内sourceNamespace。旧类型/阶段/场景通过显式适配，缺ID日志以date/text/at哈希和出现序号生成来源ID。文件作者、空间、角色不参与授权。映射按目标空间+来源+实体类型+旧ID，预览仅计算稳定目标UUID，不写映射或业务。服务器版本偏离上次导入版本或对象在回收站时报告冲突并默认保留。断链字段计入报告，确认前可取消。

流式解析依赖固定版本stream-json 3.8.0、stream-chain，采用官方令牌和数组流接口，参考 https://github.com/uhop/stream-json 。新旧格式均经字段、日期、枚举、UTF8正文和数据库不变量校验。旧时间作为来源元信息，不能冒充当前服务器版本时间。

确认导入：POST `/imports/{jobId}/commit`，Owner、CSRF和幂等key，`{planHash,confirm:true,decisions?:[{entityType,sourceId,action}]}`，action为apply_import/keep_server/skip。自动生成一份含回收站的空间业务导出，成功后才排队；该导出是业务修复引用，不代替F46数据库备份。
worker持有job行锁和空间导入锁，锁定成员资格、工作空间与触及实体并重校验Owner、时效、planHash和全部版本。按项目/任务/知识/日志/台账/关系顺序，单事务写业务、usage最大值、修订去重最近5条、映射、beforeImage/appliedVersion、审计与成功状态。任一异常整次回滚，基础故障最多三次重领，PLAN_STALE及权限错误停止。正文保留时usage仍取最大值，不相加、不减少；skip不合并附属数据。

POST `/imports/{jobId}/cancel`：仅提交前状态可取消，正在事务提交和已成功均409，禁止把修改job状态当撤销。
GET `/imports/{jobId}/recovery`：Owner受控读取导入前业务备份ID、逐实体旧值/映射/应用版本、当前版本和新增关系记录。safeToRestore是保守版本检查，知识因独立usage始终要求人工核对，恢复不得降低计数或覆盖后续编辑；报告有效期随job24h。当前提供恢复材料和独立业务备份，数据库恢复使用F46脚本，不提供盲目一键撤销。
