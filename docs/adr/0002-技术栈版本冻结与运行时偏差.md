# ADR-0002 · 技术栈版本冻结与运行时偏差

- 状态：已接受（F03）
- 日期：2026-11-03
- 关联：R27、R30；方案第 5 节；[架构与版本矩阵](../架构与版本矩阵.md)

## 背景

方案要求 F03/F04 落地精确版本矩阵，包括 Node、pnpm、React、NestJS、Prisma、PostgreSQL、浏览器与镜像摘要。本机实际情况是 Node 22.23.4（方案建议 26 LTS）、TypeScript 最新为 7.0.2、Prisma 最新为 8.0.0-rc、无 Docker。

## 决策

1. **Node 固定 22.23.4**：`engines.node = ">=22.23.4 <23"`。代码不得使用 Node 26 独有 API；升级单独立项，需跑完整回归。
2. **TypeScript 固定 5.9.3**，不使用 7.x：
   - NestJS 依赖 `emitDecoratorMetadata` 与 `experimentalDecorators`，5.9 线是当前已验证组合；
   - Prisma 7.10.1 的 peer 要求为 `typescript >= 5.4.0`，5.9.3 满足；
   - 7.x 为原生编译实现，工具链（lint、装饰器、类型生成）兼容性未经本项目验证，不在此阶段引入。
3. **Prisma 固定 7.10.1 稳定线**，不取 8.0.0-rc（方案明确“不追随 RC”）。7.x 使用 driver adapter（`@prisma/adapter-pg`）与 `prisma-client` 生成器；F05 落地时在 FS005 记录实际生成物与初始化代码，不沿用 6.x 写法。
4. **前端依赖固定** React 19.3.1 / Vite 8.3.5 / React Router 7.18.5 / TanStack Query 5.105.3；不引入 UI 组件库、图标库、图表库、日期库（图标与 SVG 图自绘，日期用 `Intl`，见 ADR-0005）。
5. **所有依赖写精确版本，无 `^`／`~`**；`pnpm-lock.yaml` 入库；CI 使用 `--frozen-lockfile`；发布禁止临时 `latest`。
6. **本机无 Docker**：F43 前由项目所有者提供容器能力，否则 F43～F47 标“阻塞”，不以本地进程替代生产镜像验收。
7. 生产镜像 digest 在 F43 记录；本 ADR 不编造 digest。

## 后果

- 22 与 26 的差异需要在代码评审时检查（不使用 `node:FSWatcher` 新选项、新的 `fetch` 行为差异等）。
- TS 5.9 无法享受 7.x 编译速度；换来装饰器与类型生成稳定。
- 依赖升级需 ADR + 回归，不能顺手 `pnpm update`。

## 复核时点

- F04：安装后核对 `pnpm why` 与锁文件，确认无隐式升级。
- F44：CI 冻结安装成功后复核 Node 支持状态。
- 每季度：评估 Node 26 / TS 7 / Prisma 8 的升级窗口。
