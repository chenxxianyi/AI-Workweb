# 数据迁移验收

本机技术验收采用独立aiwb_test和合成数据，不触碰现有开发/正式数据。

- schema1：旧中文阶段、知识类型、场景和P0/P1/P2显式转换，缺ID日志的重复内容按哈希+序号保留；文件作者和空间不参与授权。F30有15项预览验证，F31有19项确认/回滚检查。
- schema2：来源空间真实导出→空目标空间预览→确认合并→目标再导出。FS032/roundtrip.log中10项通过，逐项比较projects/tasks/entries/logs/ledger全部业务字段以及任务知识引用、标签、UTF8正文、修订、useCount和lastUsedAt。相同文本的两条日志仍为两条。
- 明确排除逐字节比较：目标UUID按来源映射重建，version从1开始，服务器createdAt/updatedAt及活动时间按实际导入建立，job与哈希为运行状态。来源createdAt/updatedAt和原元信息在originMetadata中单独保留并实际断言，不能冒充新的服务器版本时间。
- 重复导入同来源文件不增加日志、实体、关系或修订；usage取最大值与较新使用时间，不累加、不降低。
- 确认前取消不写业务，已提交不能取消冒充撤销。请求结果未知时保持原操作key或已知jobId继续查询，组件测试覆盖不另建任务。数据恢复报告提供旧值和版本边界，不能忽略用户后续编辑。

业务JSON便于迁移，不能替代数据库全量备份。实际本机数据库加密备份和恢复在F46单独演练。Safari和异机灾备按ADR-0009列后续扩展。
