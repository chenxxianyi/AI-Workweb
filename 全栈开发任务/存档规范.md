# 全栈逐步存档规范

> 本次沿用“每一步建立一个存档点”的要求，编号独立于旧单文件任务。
> FS000＝规划基线；F01～F52分别对应FS001～FS052。当前仅预建记录，不代表功能已完成。

## 1. 每一步的存档内容

| 材料 | 必须说明的内容 |
|---|---|
| 任务与需求 | F编号、需求ID、实际范围、剩余事项、下一任务 |
| 源码与契约 | 文件、Git提交／工作区状态、OpenAPI及版本、锁文件hash |
| 数据库 | 迁移前后版本、迁移文件hash、DDL／数据回填、兼容与恢复方法 |
| 环境与产物 | Node／包管理器、数据库版本、web/api/worker镜像digest、配置变量名 |
| 测试与验收 | 环境、输入、预期、实际、通过／失败、截图或报告 |
| 备份与恢复 | 受控备份位置的引用、hash、恢复验证时间与结果；不得把生产明文或密钥放入普通快照 |
| 快照完整性 | 时间戳版本目录、文件清单、SHA-256、失败材料与重试说明 |

F01～F03尚无代码、DB或镜像时写“不适用：尚未进入该阶段”，不能随意编造版本。开发阶段已建立的内容不能继续写不适用。

## 2. 目录

```text
全栈开发任务/
  任务开发文档.md
  任务/F01-....md ... F52-....md    每步独立执行文档
  任务进度.md
  存档规范.md
  验收证据/FSxxx/                  运行后填写，脱敏
  工具/保存全栈存档.ps1
  存档/FS000/存档记录.md
  存档/FS001/存档记录.md ... FS052/存档记录.md
  存档/FSxxx/版本/时间戳-随机后缀/
    files/                        当前方案／任务包、实际源码及受控证据
    快照说明.md
    manifest.json                 路径、字节数、SHA-256及可读取的Git元信息
```

历史版本不覆盖；失败版本也保留并标记未通过。任务进度登记实际的时间戳目录，不能只填写“已存档”。

## 3. 保存流程

1. 完成本步，运行相关检查；先填写FS记录，未完成项如实列出。
2. 将脱敏测试报告／截图／fixture放入对应验收证据目录；较大的CI产物、镜像和备份用受控引用及hash。
3. 复查源码和证据未包含真实密码、token、会话state、生产导出及密钥；脚本的文件名过滤不能代替秘密扫描。
4. 在项目根目录运行：

```powershell
pwsh -NoProfile -File ".\全栈开发任务\工具\保存全栈存档.ps1" -Checkpoint FS001 -Note "F01 范围与验收责任已确认"
```

5. 脚本复制指定开发文件，生成manifest并核验源／目标与归档hash；它不执行数据库迁移、构建镜像、读取浏览器数据、上传文件或提交Git。
6. 核验后在进度表填写版本路径、日期和状态。有快照不等于验收通过，脚本不自动把任务标完成。
7. 下一步开发基于最近一个验收通过版本；返工时另存版本，不修改旧快照。

当前环境使用允许本地脚本的PowerShell7（pwsh）；不修改执行策略。如果环境不允许运行脚本，按已有规范人工复制同样的材料并生成SHA-256清单，不绕过管理策略。

## 4. 自动归档边界

脚本归档：当前全栈方案、原始功能方案、README、全栈任务包及各FS记录；已存在的apps、packages、database、infra、tests、docs；选定的根配置与CI工作流。

脚本跳过旧快照、node_modules、构建／覆盖率／浏览器trace目录、数据库卷、备份目录、真实.env、证书私钥、数据库文件和典型dump文件。允许无真实值的.env.example。PNG等脱敏证据可保存；单文件超过50MiB会停止并要求改为受控引用。

脚本不会自动证明代码里没有内嵌凭据；不会下载CI产物、Docker镜像或生产备份。文件快照与镜像／备份是不同材料，完整恢复必须结合记录中的版本与引用。历史单文件任务不复制进每个全栈快照，仍保留在原目录与CP基线中。

## 5. 回退规则

- 文档任务：核验hash，复制前一通过版本中对应文档，保留当前失败版本。
- 代码任务：优先用独立分支／工作目录复原提交，或从files复制；按锁文件重建依赖，重测相关功能。
- 数据库：先检查已应用迁移与旧代码兼容。禁止因源码回退就盲目撤DDL；优先兼容前向修复。
- 必须恢复DB时：按运维手册停写、保存当前数据、在隔离库演练、明确恢复点和新增数据处理，再切换。
- 部署任务：用记录中的不可变镜像digest复原，确认web/api/worker匹配。
- 浏览器草稿：独立于代码和DB；恢复前先导出未同步内容，不能让另账号读取。

## 6. 最终归档

F52核对52步记录、需求矩阵、代码／契约／迁移、CI产物、镜像、UAT、恢复／回退演练和生产运行结果。所有引用必须可访问且hash可核验。归档不包含真实密钥；密钥保管位置和访问责任单独受控。

FS000仅证明规划文档与存档机制准备完成，不证明前后端或生产系统已交付。
