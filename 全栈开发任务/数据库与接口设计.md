# 数据库与接口设计

> 版本V2.0｜2026-11-03。实现前由F03冻结OpenAPI，由F05落地迁移。本文是待实现设计，不是已经创建的数据库。
> 应用范围：[全栈总方案](../AI编程工作台-全栈全流程开发方案.md)。

## 1. 数据归属、时间与通用字段

所有业务查询先由会话识别user，再验证workspace_members，再执行该空间查询。禁止只按对象id查数据后依赖前端隐藏。

除账号、会话和个人偏好外，业务实体必须有workspace_id。核心实体projects/tasks/entries/development_logs/ledger_records包含：

| 字段 | 数据库类型 | 规则 |
|---|---|---|
| id | UUID | 服务端生成；指定离线新建可接受经验证的客户端UUID |
| workspace_id | UUID | 非空FK，查询和变更必带空间边界 |
| created_by | UUID | 来自会话，不接受客户端伪造 |
| created_at / updated_at | TIMESTAMPTZ | 服务器UTC时间 |
| version | INTEGER | 从1递增，只对相关业务内容变化递增 |
| deleted_at | TIMESTAMPTZ NULL | 软删除标记，正常查询必须排除 |
| origin_metadata | JSONB NULL | 旧数据来源标识和来源时间，不作为在线授权或冲突依据 |

日期字段用DATE，不将“2026-11-03”当UTC时刻；共享业务的今日按workspaces.timezone计算。时区默认Asia/Shanghai，仅Owner可修改且必须确认对日期统计的影响。

每个核心表除全局id主键，还定义UNIQUE(workspace_id,id)，供复合外键使用。TaskEntry、EntryTag、项目关联及台账知识关联使用workspace_id参与的复合外键，数据库也拒绝跨空间串联。ORM生成不出的约束用可审查SQL迁移补齐。

邀请已有用户只建立成员关系，不重设密码；新用户经邀请设置本人密码。移除成员与角色变更事务内锁住成员集合，防止并发移除最后Owner。

| 表 | 业务字段 | 必要约束 |

| entry_usage | workspace_id,entry_id唯一,use_count,last_used_at | 统计与正文version分离；use_count非负；复制事件幂等 |

数据库CHECK与后端DTO双重校验关键数值、枚举及大小。草稿可缺summary，verified不可缺；标签和stack数组限制元素数量。日期由DATE及后端共同校验，不接受不存在的年月日。

项目进度不保存自动计算的冗余真值：manual=true返回manual_progress，否则按有效任务done/总数计算并四舍五入，无任务为0。last_activity_at在项目或关联任务／条目／台账实际内容变化时更新；复制计数和浏览不算项目开发活动。

首次实现默认不启用数据库RLS，以统一Repository边界、复合外键和越权测试为必需防线。后续如启用RLS，必须专门设计连接池事务上下文和非owner运行账号；不能写上策略名称就声称获得隔离。PostgreSQL明确了RLS默认拒绝及表owner等例外。[官方RLS说明](https://www.postgresql.org/docs/17/ddl-rowsecurity.html)

## 3. 索引、查询与删除

### 3.1 必建索引

- 核心表(workspace_id,updated_at DESC,id DESC)且deleted_at IS NULL，支持稳定分页。
- tasks(workspace_id,status,due_date,id)、tasks(workspace_id,project_id,status)的有效记录索引。
- development_logs(workspace_id,log_date DESC,created_at DESC,id)。
- entries(workspace_id,status,type,updated_at DESC,id)和entries(workspace_id,project_id)。
- tags(workspace_id,name_normalized)唯一；entry_tags(workspace_id,tag_id,entry_id)。
- ledger_records(workspace_id,record_date,scene)、ledger_records(workspace_id,project_id,record_date)。
- sessions(token_hash)、sessions(user_id,revoked_at,absolute_expires_at)。
- jobs(state,lease_until,created_at)、audit_events(workspace_id,at DESC,id)与external mapping组合唯一。

搜索使用参数化SQL，先按workspace、有效记录、筛选条件缩小候选；ILIKE中将%与_按搜索字面量处理。排序为标题匹配、标签、摘要正文，再加近期使用／次数，最后updated_at和id稳定排序。查询长度1～100字符，前后空白移除；空查询显示常用／最近，不执行全表热度搜索。

pg_trgm作为测量后可选索引，用EXPLAIN ANALYZE与真实中文短词验证，不假定两字词能获得三元组索引同等收益。[官方pg_trgm说明](https://www.postgresql.org/docs/17/pgtrgm.html)

### 3.2 删除与恢复

- 普通删除为软删除；默认列表、紧急统计、进度及搜索均排除deleted_at非空数据。
- 项目优先使用“归档”而非删除。软删除项目不删除关联任务／知识／台账，界面显示“原项目已删除”。
- 软删除知识不物理删关联行，但正常页面不展示该知识；恢复时只恢复仍然有效的关系。
- 硬删除项目前在同事务将子实体project_id置空；外键采用RESTRICT，禁止直接绕过业务硬删。
- 硬删除任务／条目时清理关联行；硬删条目前将台账entry_id置空，修订／使用数据再删除。
- 恢复不自动复活已删除的父对象；必须确认链接目标仍在同空间且有效。
- 30天到期清理由有审计的后台任务执行；导出业务包默认只含有效数据，是否含回收站须显式选择并另做权限检查。

## 4. 后端结构与公共API契约

Controller处理协议；Guard建立用户与成员上下文；Service校验业务并组织事务；Repository强制空间参数。公共DTO不能暴露内部路径、哈希、SQL、密码或堆栈。

- 根路径：/api/v1；空间业务：/api/v1/workspaces/{workspaceId}/...
- 成功：{ data, meta?:{nextCursor,hasMore}, requestId }；错误：{ error:{code,message,fieldErrors?}, requestId }。
- GET详情返回ETag，实体响应含version。PATCH/DELETE/restore使用If-Match；前端不能自行猜版本。
- 默认limit=20，最大100；cursor必须绑定空间、排序与筛选指纹，改变筛选后丢弃旧cursor。
- offset不用于大表正常滚动；游标分页不承诺跨多次请求的一致快照，导出另用一致性快照。
- 普通JSON请求体默认128KiB；传输文件单独流式上传，默认≤512MiB、≤25万条实体，单条正文仍≤20KiB。
- 超限返回明确错误，不截断内容；需要更大规模时先压测调整或分包导入，分包提交不是全包原子事务。
- 日期参数只接受YYYY-MM-DD，时间戳是服务器UTC ISO8601；禁止客户端提交created_by/role等系统字段。

| HTTP状态 | 场景 |
|---|---|
| 400 | JSON／查询语法错误 |
| 401 | 未登录、会话过期或已吊销 |
| 403 | 已确认成员但角色无权；CSRF或来源校验失败 |
| 404 | 对象不存在或不属于可访问空间，避免探测其他空间对象 |
| 409 | 幂等键与请求体不一致、业务冲突、预览计划过期 |
| 412 | If-Match版本过期，返回可授权查看的当前version及字段 |
| 413 | 请求／文件超过限制 |
| 422 | 字段或业务校验失败 |
| 428 | 条件写入缺少If-Match |
| 429 | 登录、搜索或高成本接口限流 |
| 503 | 数据库或服务暂不可用；写入结果未知时通过幂等状态查询 |

认证cookie默认同源，不启用任意CORS。开发跨端口通过Vite代理/api解决。生产HTTPS会话与CSRF实现细节必须用选定稳定版本文档核对；认证机制不能用伪造前端布尔值替代。

## 6. 条件写、幂等与事务

### 6.1 典型更新

客户端GET task返回version=4、ETag="4"。PATCH同时提交If-Match:"4"；数据库UPDATE ... WHERE id、workspace_id、version=4、deleted_at为空。成功将version变5；更新数为0时区分无权／不存在和版本冲突，不能先读后无条件UPDATE。

任务完成与done_at同事务维护；取消完成清done_at。正文修订锁定对应条目，保存旧正文、更新version和裁剪5版一次提交。

### 6.2 幂等

幂等范围为账号+空间+动作+key，请求hash排除可变CSRF头但包含业务体。首次处理用唯一约束占位，业务变更与结果引用同事务提交；并发同key不能同时创建。相同key不同body返回409。

普通幂等响应默认保留7天；指定离线事件有效期7天，超过期限的客户端操作不自动重发，转人工确认／导出，避免过期去重后重复执行。未完成／结果未知的传输任务继续按jobId查询，不以重发新key代替恢复。

### 6.3 事务边界

- 沉淀：校验任务与权限→新条目→任务关联→任务version→审计→幂等结果。
- 回滚：版本校验→当前正文入修订→选中正文成为当前→裁剪→version→审计。
- 角色：锁成员行／空间→校验至少一个owner→变更→吊销或重校验访问→审计。
- 导入：锁空间导入控制范围→重新验证planHash及触及实体version→按外键顺序合并→关系与统计→映射→审计→job成功；任何一步失败回滚。
- 清空：owner重新认证→确认空间名和备份提示→事务清空该空间业务与关联／统计→保留身份与成员→审计。

所有事务失败都给稳定错误码，不吞错或把部分失败当成功。作业状态失败的写入在业务事务回滚后另行落盘；进程中断靠租约与幂等恢复。

## 7. JSON迁移与任务状态机

### 7.1 文件格式

旧格式schema=1为原方案projects/tasks/entries/ledger/logs/settings快照。新格式schemaVersion=2包含exportedAt、来源命名空间、业务实体及关联、最多5条修订、使用统计与必要来源元信息；不包含users、sessions、邀请、密码、角色权限、生产配置或密钥。

新版本文件通过显式适配器读取；未知高版本拒绝。所有目标数据归当前已授权空间，导入文件中的workspace_id、created_by和角色不能改变授权。

迁移到新数据库时业务id可映射、服务端version和updated_at重新建立；旧时间保存在origin_metadata，不能当作新的服务端时间。往返测试比较业务字段、来源时间、关系、修订和计数，并单列解释映射、版本、job状态等运行字段差异，不能宣称两个JSON逐字节相同。

### 7.2 旧ID映射与冲突

首次导入选择source_namespace，后续同一旧库继续选择同一namespace。不同来源旧库即使id相同也不得混为同一来源。映射键为workspace+namespace+entityType+legacyId，新UUID关系按映射重建。

旧日志缺id时，用规范化date/text/at内容hash+同内容出现序号生成稳定来源id；缺时间置来源0，不用当前时间冒充更新。相同文件再次预览产生相同映射，不重复创建。

已映射数据若服务器version仍等于last_imported_version，可比较来源时间决定更新；服务器已被用户编辑则列为冲突，默认保留服务器。即使导入文件声称“时间较新”，也不能静默覆盖服务器编辑或复活回收站对象。

同一映射条目的usage合并取use_count最大值、last_used_at较新值，不相加、不减少现有统计；修订按正文hash与来源时间去重，再保留最近5条。来源不同的条目不因正文相同自动合并。before_image和applied_version用于检查导入后的恢复是否会覆盖后续编辑，其清理与访问同样受job权限和保留期约束。

### 7.3 状态

uploaded → validating → preview_ready → queued → running → succeeded / failed / cancelled / expired。

validating只写暂存与job，不改业务表；preview展示各表新增／更新／保留／冲突／拒绝／断链。默认24小时内确认，超时或触及实体版本变化返回PLAN_STALE并要求重算。

worker通过数据库锁和lease领取任务；运行中定期续租；崩溃后可重领但同job业务只能提交一次。最多3次可重试基础故障，业务校验失败不自动重复。完成结果、下载文件和暂存默认24小时清理，审计和必要结果摘要保留。

取消仅在业务提交前生效：排队任务可直接取消，运行任务在受控检查点响应取消并回滚未提交事务；已提交任务不能靠改状态撤销，须走有版本检查的修复／恢复流程。

导出worker在同一数据库REPEATABLE READ快照内读取所有业务表，保证关系一致；流式写内部持久临时卷，先完成文件再开放下载。使用随机服务端文件名，下载走认证API，不直接暴露文件目录。

大批量变更前保存可恢复的数据库／空间备份引用；导入job内的旧值用于业务修复，不代替异机灾备。恢复导入前状态前先检查后续编辑，不能盲目整库回退影响其他空间。
