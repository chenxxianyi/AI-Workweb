# F46 · 本机加密备份与隔离恢复

使用 `node scripts/backup.mjs create stage|production`。PostgreSQL17 pg_dump自定义格式通过管道直接进入AES-256-GCM，不把明文dump写入普通目录。一致快照包含24表，记录数量和行指纹、PG版本、运行版本、密文大小/SHA256/耗时；元数据作为GCM附加验证数据。

备份：`.data/backups/<环境>`；随机256位密钥：`.data/backup-keys/<环境>.key`。两处均为当前Windows用户与SYSTEM ACL，不进入普通FS快照。密钥保管人为项目所有者；同机目录分离不能抵御整盘损毁，异机副本是扩展。

恢复命令：`node scripts/backup.mjs restore <环境> <备份ID> <aiwb_restore_标识_test>`。先核验大小/hash并完成GCM验证，才新建隔离目标；拒绝已存在库、正式库、错误密钥和损坏备份。恢复临时明文位于受限runtime目录，finally清除。失败目标不自动提升为正式库。

14个实际检查包括：pg_dump/restore、24表指纹、修订/使用/任务/台账、错误密钥、损坏文件、覆盖保护、源库不变、保留策略、受限角色API、登录Owner及业务读取。小夹具实际RTO和RPO见FS046，不外推大库。日14/周8/月12恢复点策略先dry-run，--apply才清理通过完整性校验的过期文件；损坏记录单独报告。

API设置显示本机备份摘要，24小时过期与失败状态明确；每日自动执行和告警接入在F49完成。业务JSON导出不是数据库备份。传输临时文件不属于dump；恢复后旧下载/未提交导入应过期并重新导出/上传，正式切换前撤销恢复会话。OS角色与ACL由native初始化/授权流程重建，不从dump信任角色权限。
