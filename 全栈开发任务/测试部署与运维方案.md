# 测试、部署与运维方案

> V2.0｜2026-11-03｜执行入口F38～F52。前面每个开发任务也必须同步验证，不把测试全部推迟到收尾。
> 本文规划的是后续实际操作；当前没有启动容器、购买服务器、发送告警或部署线上系统。

## 1. 环境和配置

| 环境 | 用途 | 数据与访问 |
|---|---|---|
| local | Windows/WSL或Linux开发；Node进程+Docker数据库 | 合成数据，每人独立库；API经前端代理访问 |
| CI | 自动测试与正式构建 | 临时PostgreSQL，测试后销毁；无生产凭据 |
| staging | 生产同版本预发布、迁移与恢复演练 | 独立DB、域名、会话和密钥；仅脱敏数据 |
| production | 个人／团队日常使用 | 私有访问入口；持久卷、备份、审计和监控 |

代码、锁文件和镜像在staging、production保持同一版本，只有运行时配置不同。生产不从主机挂载源代码，不启动dev server。

配置清单至少包含：APP_ENV、PUBLIC_ORIGIN、PORT、DATABASE_URL或secret文件、SESSION空闲／绝对时限、CSRF可信来源、TRANSFER_DIR、导入大小限制、job租约、日志级别、备份目标及加密密钥引用。

仓库仅保存无真实值的.env.example；前端仅得到同源API路径和公开构建号，不得获得数据库地址、会话密钥、数据库密码或备份密钥。启动校验缺配置即失败，不使用生产默认弱密码。敏感配置通过受控文件或平台secret注入，日志输出脱敏。

## 2. 测试分层与门槛

| 层级 | 工具和对象 | 必须覆盖的风险 | 执行时机 |
|---|---|---|---|
| 静态检查 | TypeScript、格式／lint、契约差异 | 类型错误、无效导入、意外破坏API | 每次提交和CI |
| 单元 | Vitest／Node测试；日期、排序、校验、统计 | 跨月跨年、闰年、时区、UTF-8、排序与无匹配搜索 | 改对应纯函数时 |
| Service测试 | 领域事务入口与策略 | 最后Owner、状态迁移、幂等、版本冲突、修订上限 | 模块开发时 |
| 数据库集成 | 真实PostgreSQL17测试库 | 复合FK、事务回滚、唯一约束、游标、SQL过滤 | API开发和CI |
| API集成 | HTTP+会话+真实DB | 未登录、三角色、跨空间访问、CSRF、错误码 | 每个接口完成时 |
| 浏览器E2E | Playwright+真实API | 登录到沉淀闭环、下载导入、多设备、网络断开 | 模块联调和发布候选 |
| 真机／人工 | 手机、Safari、键盘 | 375px、安全区、剪贴板、输入法、焦点、安装体验 | F42及相关UI变更 |
| 性能／恢复 | 压测脚本、故障注入、还原环境 | 大表搜索、并发更新、worker重启、DB恢复、版本回退 | staging和发布前 |

Playwright提供Chromium、WebKit、Firefox自动化；浏览器内核测试不替代目标Safari/iPhone实机验收。[Playwright官方介绍](https://playwright.dev/docs/intro)

覆盖率仅作缺口指标：权限、事务、导入、条件写和日期等关键分支必须覆盖；不为了整体比例编写与实现逐行镜像的低价值测试。普通文案／可逆样式调整做针对性视觉检查，不强制新增单测。

## 4. 账号、空间和输入安全测试

构造空间A/B，用户A-owner、A-editor、A-viewer、B-owner以及已移除用户。对每个详情、列表、修改、删除、关系、搜索、统计、导入导出、job下载和回收站接口逐项验证：

- 无会话返回401；已知空间内无角色权限返回403；其他空间对象返回404。
- 改URL、请求体workspaceId、createdBy或role不能提升权限。
- 关系ID属于另一空间时，Service与复合FK均阻止落库。
- Viewer不能绕过页面直接写业务，复制事件仅允许受限统计字段。
- 最后Owner不能被删除或降级；并发两次角色变更也不能把Owner清空。
- 退出、改密、禁用账号和移除成员后，已持有cookie的API请求不能继续访问。
- CSRF空令牌、错令牌和错误Origin被拒；不以SameSite代替测试。
- HTML事件、script、危险Markdown href、引号闭合、SQL通配及注入输入不能执行代码或扩大查询。
- 登录按账号与IP限流，返回不区分“账号不存在／密码错误”的通用信息；不把token或密码写日志。
- 导入文件名不参与服务器路径拼接；内部文件不可经静态目录直接下载。
- 发布扫描依赖与镜像；严重风险关闭或有明确可验证的修复措施，不把扫描通过当成所有安全问题都不存在。

密码、会话、CSRF实现参照[OWASP密码存储](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)、[CSRF建议](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)，并在F08/F09记录实际库版本和参数校准结果。

## 5. 数据事务、导入和弱网测试

- 在沉淀、回滚、清空和导入事务第2/3步注入错误，所有业务表保持一致；错误作业状态能另行记录。
- worker处理时杀进程并重启：租约过期后可重领，同job不重复应用。
- 导出发生时持续编辑业务，包内关系和内容来自一致快照，不能出现新子对象配旧父表。
- 预览后另一设备修改对象，再确认导入：计划过期返回409，不静默执行旧计划。
- schema1旧ID映射、缺日志id、时间缺省、同id跨来源、已有服务器编辑、回收站冲突均有样例。
- schema2导出→空空间导入→再导出，逐字段比较业务值、来源时间、关系、修订和使用统计；单列ID映射、服务器时间与version重建差异。
- 文件超限、正文超限、未知schema、坏JSON、重复id、孤立引用、取消上传不修改业务。
- 断网后写日志／新草稿／任务状态：显示待同步；恢复后原幂等键提交。
- 离线更改任务与服务器新版本冲突：保留本地意图，显示冲突，由用户确认。
- 退出／切换账号／移除成员：缓存不得串账号串空间；未同步草稿有明确保留或导出路径。
- 浏览器配额满时草稿保存失败有提示；网络正常时服务器写入仍可继续，不能误判数据库已满。
- 请求成功但响应丢失：按幂等状态恢复结果，不重复创建。

## 6. 性能与资源基线

候选机器按2vCPU、4GiB内存、40GiB SSD起步规划；这是压测起点，不是无需验证的采购承诺。测试报告记录CPU、内存、磁盘、系统、镜像、数据库参数和网络条件。

准备每空间1万知识、5万任务、5万台账以及多空间数据，包含长正文、中文短词、热门标签和不同月份。20并发下持续运行至少15分钟；分别记录读接口、写接口、搜索、聚合、job耗时的p50/p95/p99、错误率、CPU/内存和连接池情况。

- 普通列表／详情API p95≤300ms，聚合／搜索p95≤800ms，正常场景错误率<1%。
- 前端首屏主要内容≤2秒，记录同区受控网络；不混用服务端耗时和页面加载时间。
- 压测不能把缓存命中率100%当冷启动能力；短查询和空结果要单独测。
- 用EXPLAIN ANALYZE定位SQL；避免N+1、无限列表和把所有正文送到首页。
- 长任务限并发，初始单worker；导入上传流式落盘，校验后分批暂存，最终提交事务；事务耗时和锁等待单独测。
- 数据库连接池、HTTP超时、job租约、限流与最大文件大小在F41按实测冻结。
- 磁盘剩余<20%提醒，<10%拒绝高体积导入／导出并告警；保留普通查询和故障处理余量。

## 7. 容器与网络部署

默认服务：

| 服务 | 内容 | 暴露范围 |
|---|---|---|
| web | Caddy + 前端静态构建 | 对用户开放80/443或VPN内入口 |
| api | NestJS正式构建 | 只在Compose内网，由web代理/api |
| worker | api同镜像的后台命令 | 无对外端口 |
| db | PostgreSQL17固定补丁／镜像摘要 | 仅内网；独立持久卷 |
| backup | 主机定时器调用已审核备份工具 | 无用户接口；受控备份账号和加密输出 |

api/worker使用非root账号，镜像不可变；配置资源限制、重启策略和日志轮转。数据库卷、传输临时卷、TLS状态卷分别管理。生产不挂载开发源码，不把数据库持久数据写容器临时层。

Caddy处理TLS与同源静态资源/API。自动HTTPS依赖域名、挑战访问与证书持久存储；只有内网域名时需选择VPN／内部CA并让终端信任证书，不能把测试自签名部署描述为所有设备自动可信。[Caddy官方HTTPS说明](https://caddyserver.com/docs/automatic-https)

静态带hash资源可长缓存，HTML短缓存，Service Worker升级需兼容旧页面；认证、业务API和下载响应默认private/no-store，显式离线副本由应用按账号空间管理。SPA路径回退不能吞掉/api错误。

## 8. CI/CD流程

采用可替换的CI平台，F04确定实际仓库平台。流水线步骤：

1. 拉取指定提交，校验锁文件，安装冻结依赖；扫描是否误入密钥。
2. lint、类型检查、纯函数／Service测试。
3. 启动临时PostgreSQL，从零应用所有迁移；跑约束、权限、事务、接口集成测试。
4. 从上个发布迁移版本升级当前版本，验证非空库升级与数据回填；数据库DDL变化需专门复查。
5. 生成OpenAPI与前端类型，检测不兼容变更；前后端正式构建。
6. 跑核心E2E；失败保留脱敏trace和日志，认证state不公开发布。
7. 扫描依赖／镜像，生成版本清单和SBOM；构建web及api镜像并按提交SHA标记。
8. 推送不可变镜像，记录digest；staging和production使用相同digest，不在服务器重新编译。
9. staging执行单独迁移job，部署web/api/worker，健康检查与冒烟。
10. 生产发布使用审核后的候选版本和维护窗口；实际执行由实施任务授权与环境访问决定。本次仅制定方案。

数据库迁移不由每个API副本启动时抢跑；使用一个受控迁移任务。开发账号可DDL，生产api账号仅具所需DML，迁移账号和备份账号分离。使用Prisma7审核迁移，不能在生产执行重置开发库的命令。[Prisma 7迁移说明](https://www.prisma.io/docs/guides/v7/database/data-migration)

## 9. 备份与恢复

### 9.1 备份内容与目标

- 生产每日一次数据库一致性逻辑备份；每次发布、危险迁移或大批量导入前另备份。
- 保留最近7天日备份、4周周备份、6个月月备份；小团队根据实际成本和数据量在F46调整。
- 至少一份加密异机副本；不能把与主库同盘的另一个目录当灾备。
- 备份数据库结构和数据；角色、扩展、权限、镜像、配置模板、迁移清单与TLS恢复策略另有重建说明。
- 用匹配数据库大版本的pg_dump/pg_restore工具；备份账号需验证能覆盖全部目标表及序列，不能只成功备份部分可读表。
- 加密密钥与备份文件分离，至少两名指定保管人或单人可恢复的受控保管方式；密钥不放任务快照。
- 备份任务保存开始／结束、源版本、字节数、hash、加密结果、上传结果与保留策略执行结果。
- RPO目标≤24小时，RTO目标≤2小时；失败备份必须告警。若业务需要更小RPO，再引入WAL归档与PITR并重新验收。

数据库逻辑备份工具和恢复方法依据[PostgreSQL备份文档](https://www.postgresql.org/docs/17/backup-dump.html)。仅有dump文件不能保证角色、权限和外部配置都已备齐。

### 9.2 恢复演练

1. 在隔离恢复环境准备相同数据库大版本、扩展、角色和应用镜像；不直接覆盖生产。
2. 校验备份hash和解密能力，将备份还原到空库，应用所需兼容迁移。
3. 比较各表条数、关系、关键样本、修订、计数及作业状态。
4. 启动API验证登录、空间隔离、今日、知识搜索、沉淀、台账与导出。
5. 记录还原耗时、数据恢复点、实际RPO/RTO、丢失窗口与修复事项。
6. 首次上线前、每月至少一次及重大迁移后演练。实测超目标则修正方案，不把目标当结果。

业务JSON导入只能迁移一个空间的业务，不恢复全部账号／会话／权限；数据库灾备恢复是另一条流程。

## 10. 发布与回退

### 10.1 生产发布清单

- 发布号、Git提交、web/api镜像digest、迁移版本、配置变更、测试报告可查。
- UAT与目标浏览器通过；无未关闭阻断问题。
- 维护窗口与负责人明确；备份及至少一次恢复演练可查。
- 先部署兼容的数据库扩展迁移，再部署应用；确认旧应用仍可读写兼容schema。
- 切换后验证live/ready、登录、空间隔离、CRUD、沉淀、搜索、图表、导入导出。
- 观测至少30分钟的错误率、延迟、job、数据库连接和日志，再结束维护。
- 上线后24小时复查核心功能、容量、备份任务和告警。

### 10.2 回退分类

| 故障 | 处理 |
|---|---|
| 仅前端问题 | 回到上个已验收web镜像digest，检查Service Worker和API契约兼容 |
| API问题，schema向后兼容 | 回到上个api/worker同版本镜像，暂停不兼容新job，复测 |
| 迁移失败且事务已回滚 | 保持旧应用，修正迁移后前向修复，不能改写已发布迁移文件 |
| 新schema与旧应用不兼容 | 优先前向修复或兼容补丁，不承诺一键降级 |
| 必须还原数据库 | 停写、保存当前副本及新增业务、明确恢复点与损失窗口，在隔离环境验证后切换 |
| 单次导入错误 | 优先按job记录修复该空间触及数据，检查后续编辑，不整库恢复影响其他空间 |

Expand／contract分版本执行，删除旧列放在后续版本。F47必须实际演练镜像回退和数据恢复两条路径，记录耗时、兼容窗口和可恢复范围。

## 11. 监控、告警与日常维护

| 监控项 | 初始阈值／频率 | 负责人需采取的动作 |
|---|---|---|
| 可访问性／ready | 每分钟探测，连续3次失败 | 查看代理、API、DB状态，按故障手册恢复 |
| API错误率 | 5分钟>1%，过滤预期4xx | 用requestId定位错误，判断回退 |
| API延迟 | 连续10分钟高于既定p95预算 | 查看慢SQL、连接池、worker与资源 |
| 磁盘 | <20%预警，<10%严重 | 清理已过期传输文件／日志，扩容前验证备份 |
| DB连接与CPU／内存 | 按F41实测设置 | 排查泄漏、慢事务和并发 |
| job | lease超时、积压>5分钟、失败 | 检查worker，幂等重试或人工修复 |
| 备份 | 24小时无成功异机副本 | 立即排查，冻结危险发布 |
| TLS证书 | 距过期<14天且续期异常 | 检查DNS／挑战／持久卷和网络 |
| 登录异常 | 频繁失败／限流 | 检查攻击或错误配置，按账号恢复流程 |

日志采用JSON，包含时间、级别、requestId、脱敏user/workspace、路由、耗时、结果；不记录密码、cookie、token、完整请求正文或导入全文。应用日志默认14天，审计默认180天，可按实际容量调整；备份、作业、审计的清理都有记录。

告警通道在F49指定实际接收人和渠道并演练，在F50生产发布前可用，只在需要处理的故障／恢复时通知。本次方案编制不会发送邮件、消息或创建外部定时任务。小规模可使用平台监控和日志检索；Prometheus/Grafana在确有需要时引入。

每日检查备份与关键错误；每周检查容量与job；每月做恢复演练、补丁评估和成员权限复查。漏洞补丁按影响评估及时处理，数据库大版本升级另建兼容与恢复任务。
