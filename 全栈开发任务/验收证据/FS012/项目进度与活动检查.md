## 3. 关键设计取舍

| 取舍 | 原因 |
|---|---|
| 归档用独立 `archived_at`，不复用 `deleted_at`/stage | 软删除属于回收站（F34），归档是“从进行中移出但保留可查”；混用会让回收站语义混乱 |
| 进度在读取时计算，不落冗余字段 | 任务状态随时变化；写时冗余需要额外一致性维护，读取时聚合成本低（一次 groupBy） |
| 手动模式写入 `manual_progress`，自动模式强制为 NULL | 数据库 CHECK 保证不会出现“自动模式带着旧手动值”的脏数据 |
| 校验失败在服务层抛 422，不依赖 DTO only | `repo`/`color` 规则是业务规则（编号、颜色白名单），需要与前端提示共用文案 |
| 游标绑定 `(last_activity_at, id)` | 活动时间会因内容变化而更新，用 `updated_at` 不稳定；`id` 兜底保证唯一 |
| `touchActivity` 单独暴露 | F14/F19/F26 的任务／知识／台账写入需要更新项目活动时间，避免各模块自己拼 SQL |
