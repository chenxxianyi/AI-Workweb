## 3. 关键设计取舍

| 取舍 | 原因 |
|---|---|
| 状态转换单独接口 | 普通 PATCH 若允许带 `status`，编辑时就能绕过“转 verified 需完整”的校验 |
| 用字节而不是字符限制正文 | 需求是 20KB；中文 1 字 3 字节，按字符限制会让中文用户实际可用空间缩水 3 倍 |
| 草稿允许空标题（新迁移） | 需求允许“先记一条空草稿”，但 F05 的 CHECK 要求标题 ≥1 字符；改为只保留上限，完整性交给 `entries_verified_complete_ck` |
| 正文变更写入 revision | 仅靠 `updated_at` 无法回溯；保存旧正文比保存新正文更能解释“改之前是什么” |
| 标签归一化后共享 Tag 行 | 避免 “React/react/REACT” 变成三个标签；同空间唯一约束兜底并发 |

| D-F19-01 | 空壳草稿创建 500（`entries_title_len_ck` 违反） | F05 约束要求 title 至少 1 字符，与“草稿可缺字段”冲突 | 新迁移放宽为只校验上限；verified 完整性仍由 `entries_verified_complete_ck` 保证 |
