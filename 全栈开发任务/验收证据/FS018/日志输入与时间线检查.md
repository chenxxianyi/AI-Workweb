## 6. 关键设计取舍

| 取舍 | 原因 |
|---|---|
| 输入区用 textarea + 显式键盘判定 | 多行备注需要 Shift+Enter；中文输入法在候选框确认时也会发 Enter，必须识别组合态 |
| 同时判断 `isComposing` 与 `keyCode === 229` | 前者是标准，后者是 Safari/旧 Chromium 在组合期上报的 legacy 值，双保险 |
| 成功后才清空输入 | 失败要保留用户写的内容（F18-03），只在 `onSuccess` 清空 |
| 默认记录日期取 `/dashboard/today` 的业务日 | 与后端校验口径一致，避免跨时区用户被 422“未来日期” |
| 删除后焦点回到输入框 | 对话框关闭后焦点不能丢在 `<body>`，否则键盘用户失去位置 |
