## 4. 关键设计取舍

| 取舍 | 原因 |
|---|---|
| 完成/撤销只在服务端返回后更新界面 | 失败不能显示成功（F16-01）；成功提示以提交结果为准 |
| 撤销条 8 秒后自动消失 | 避免长期占用注意力；撤销本身是再次 PATCH（带新版本） |
| 412 时提示 + 重新拉取 | 用户能看到“被别人改了”，并拿到最新版本，而不是静默覆盖 |
| 创建复用同一幂等键 | 超时重试不会重复新建（服务端 F14 已证明同键只执行一次） |
| 顺延必须先预览再确认 | 避免误改“更早逾期”与“已完成”任务 |
| 列表按 `data-task-title` 标记行 | 让 E2E 定位稳定（也便于 F40 端到端测试） |

## 7. 缺陷与修复

| 编号 | 现象 | 根因 | 修复 |
|---|---|---|---|
| D-F16-01 | E2E 点“完成”误伤其他任务 | `div:has-text(...)` 匹配到了包含多行的祖先元素，`.last()` 取到别的按钮 | 给任务行加 `data-task-title`，E2E 用属性精确定位（非产品缺陷，但暴露了定位脆弱性） |
| D-F16-02 | 412 用例第一次未触发 | 在数据库改版本后又重新加载页面，UI 拿到了新版本 | 改为“页面保持旧状态 → 改库 → 直接点击”，正确触发 412 |
