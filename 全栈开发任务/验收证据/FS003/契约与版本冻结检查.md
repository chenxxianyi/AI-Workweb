## 3. F03-01 主流程与交付物

| 检查 | 实际 |
|---|---|
| 没有混用 ORM 主版本 CLI | `prisma`、`@prisma/client`、`@prisma/adapter-pg` 三者冻结为同一 `7.10.1`；矩阵第 2 节与 ADR-0002 明确“CLI 与 client 同版本，不取 8.0.0-rc” |
| 鉴权可据此实现 | ADR-0003：cookie 名、`HttpOnly`/`SameSite`/`Secure` 规则、会话 24h/7d、登录轮换、CSRF 双提交、失败码 `CSRF_INVALID`、恢复 CLI 流程 |
| 分页可据此实现 | 契约统一 `meta:{nextCursor,hasMore}`、`limit` 默认 20 最大 100、`cursor` 绑定空间+排序+筛选指纹（C-13） |
| 字段校验可据此实现 | 各 Schema 的 `maxLength`／`minimum`／`enum`／`pattern` + 数据库约定第 4 节 CHECK 落点 + ADR-0005 的 `DATE` 语义 |
| 失败状态可据此实现 | 错误码表 28 条与 HTTP 类别一一对应；OpenAPI 各操作声明实际会用到的 4xx/5xx |

## 4. F03-02 代表性请求／响应（成功、422、412、428）

### 4.1 成功创建任务（201）

```http
X-CSRF-Token: 5f3a…
Idempotency-Key: 0d6b4b1e-…
Content-Type: application/json

{ "title": "完成知识库修订对比", "priority": "p0", "status": "todo",
  "projectId": "2c9e…", "dueDate": "2026-11-05" }
```

```json
{ "data": { "id": "a1d2…", "workspaceId": "8b1f…", "title": "完成知识库修订对比",
            "priority": "p0", "status": "todo", "dueDate": "2026-11-05",
```

### 4.2 字段校验失败（422 VALIDATION_FAILED）

```http

{ "title": "", "priority": "p9" }
```

```json
{ "error": { "code": "VALIDATION_FAILED", "message": "请求字段校验失败",
             "fieldErrors": { "title": ["不能为空"], "priority": ["必须是 p0/p1/p2 之一"] } },
  "requestId": "r-91bb02" }
```

### 4.3 版本冲突（412 PRECONDITION_FAILED）

```http
PATCH /api/v1/workspaces/8b1f…/tasks/a1d2…
If-Match: "3"
{ "status": "done" }
```
（服务器当前 version=4）

```json
{ "error": { "code": "PRECONDITION_FAILED", "message": "该记录已被其他设备修改",
             "currentVersion": 4 },
  "requestId": "r-5c7e10" }
```
预期 UI：打开对比面板（F02 第 3.3 节三出口），不静默覆盖（R23）。

### 4.4 缺少条件（428 PRECONDITION_REQUIRED）

```http
PATCH /api/v1/workspaces/8b1f…/entries/e77a…
{ "title": "新标题" }
```

```json
{ "error": { "code": "PRECONDITION_REQUIRED", "message": "缺少 If-Match，请携带当前 version" },
  "requestId": "r-0a1d33" }
```

### 4.5 幂等重放（同键同体 → 返回首次结果）

```http
POST /api/v1/workspaces/8b1f…/tasks/ a1d2/promote
Idempotency-Key: 7f21…   (第二次发送同一 key 与同一 body)
```
预期：`201`/`200` 返回首次创建的条目，不新建第二条（ADR-0004 第 2 条）。

## 6. 契约评审记录

评审对象：`docs/api/openapi.yaml`（由子代理按设计文档第 4、5、6、7 节编写）+ 本人复核。发现 12 处需冻结的细节，逐条决定并写入 `docs/api/契约冻结决定.md`：

- C-01 项目阶段四值、C-02 知识五类型英文名 → 采纳并同步到数据库约定；
- C-03 补 `GET /logs/{id}`（条件写需要 version），C-08 传输 202+轮询，C-11 `includeDeleted` 限定，C-12 CLI 不进 HTTP；
- C-04 补 4 个时间列，C-05 无 version 实体用幂等而非 If-Match（ADR-0004 已补范围澄清）；
- C-06 ErrorResponse 增可选 `currentVersion`/`details`，C-07 认证响应体细化，C-09／C-10 枚举与参数命名。

复核结论：与设计文档无语义冲突；契约可支撑 F06～F07 的实现与类型生成。
