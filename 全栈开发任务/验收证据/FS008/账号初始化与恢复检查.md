## 2. Argon2id 参数校准（本机实测）

| 参数 | 平均耗时 |
|---|---|
| m=19 MiB, t=2, p=1 | 34.4 ms（偏快） |
| m=64 MiB, t=3, p=1 | 165.8 ms |
| m=64 MiB, t=6, p=1 | 368 ms |
| m=128 MiB, t=3, p=1 | 349 ms |
| **m=64 MiB, t=7, p=1（选中）** | **343.7 ms**（345.4 / 346.9 / 338.8） |

选择理由：落在 0.3～1.0 s 目标区间；单次内存 64 MiB，比 128 MiB 方案更适合并发登录；
`pnpm --filter @aiwb/api auth:calibrate` 输出“结论：在建议区间内”。

## 6. 安全约束核对

| 要求 | 实现与证据 |
|---|---|
| 无通用默认密码 | `bootstrap-owner` 必须从 stdin 读密码；策略拒绝弱口令；无内置账号 |
| 恢复令牌只存哈希、30 分钟、一次性 | `account_recovery_tokens.token_hash = sha256(token)`；`expires_at = now+30min`；`usedAt` 条件更新保证只成功一次；重放/过期/伪造三类用例 |
| 改密与恢复吊销旧会话 | `session.updateMany({revokedAt: null})`，测试断言 2→0、1→0 |
| 密码与令牌不进日志/审计 | 审计摘要只写动作与计数；测试扫描 `auditEvent.summary` 不含明文密码/令牌；日志脱敏沿用 F06 |
| 错误不泄露账号存在性 | 恢复失败统一 401 “恢复令牌无效或已过期”；登录失败文案在 F09 |
| 限流 | `POST /auth/recovery/complete` 5 次/分钟；`PATCH /auth/password` 10 次/分钟；实测第 6 次 429 |
| 审计 | `account.bootstrap`、`account.password_change`（成功/失败）、`account.recovery_issued`、`account.recovery_completed` |

## 8. 缺陷与修复

| 编号 | 现象 | 根因 | 修复 |
|---|---|---|---|
| D-F08-01 | `pnpm add argon2` 中止、依赖未写入 `package.json` | 安装期 postinstall（prisma generate）异常中断整个 add | 用 `--ignore-scripts` 安装并在 `pnpm-workspace.yaml` 允许 `argon2` 构建脚本 |
| D-F08-02 | 集成脚本报 `invalid input syntax for type uuid: ""` | 测试库存在 F05 演示用户，`bootstrapOwner` 按设计拒绝第二个 Owner，后续用空 id 查询 | 集成脚本改为“仅测试库 + TRUNCATE 后从零开始”，并在库名不以 `_test` 结尾时拒绝运行 |
| D-F08-03 | 测试账号密码被自身策略拒绝 | 策略禁止密码包含邮箱本地部分（如 `owner`），测试密码正好包含 | 调整测试口令，保留策略 |
| D-F08-04 | HTTP 响应没有 `{error:{...}, requestId}` 信封 | 统一过滤器/拦截器只注册在 `main.ts`，测试与 CLI 启动的进程拿不到 | 改为在 `AppModule` 用 `APP_FILTER`/`APP_INTERCEPTOR`/中间件注册；`main.ts` 只做启动 |
| D-F08-05 | `ThrottlerGuard` 启动失败（无法解析 `Reflector`） | `@nestjs/throttler` 依赖构造参数元数据，esbuild/tsx 不生成 | 自实现 `RateLimitGuard`；移除 `@nestjs/throttler`；ADR-0008 补记 |
| D-F08-06 | 集成脚本首次运行 `TableDoesNotExist` | 重建数据库后未对 `aiwb_test` 应用迁移 | 部署 `migrate deploy`；记录测试库需先迁移 |
| D-F08-07 | 校准脚本 6 次迭代时平均 299 ms，刚好低于区间 | 阈值设为 300ms 且机器有波动 | 调 `timeCost` 至 7（343.7ms），保留 300ms 下限 |

## 10. 结论

F08 的初始化、改密与恢复链路在真实数据库与真实 HTTP 上通过（31 + 14 项），
密码与令牌只以哈希形式存库、不进入日志与审计，令牌一次性且 30 分钟过期，
改密/恢复都会吊销旧会话。**发现并修正了一个跨任务的真实缺陷（D-F08-04：信封只在 main.ts 注册），
并把不可用的第三方限流替换为首方实现。**
