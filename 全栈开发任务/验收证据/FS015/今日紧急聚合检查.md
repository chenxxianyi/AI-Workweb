## 3. 关键设计取舍

| 取舍 | 原因 |
|---|---|
| 时间阈值用“服务端 now”与“空间时区的业务日”共同判断 | 逾期是日期比较（DATE），停滞是时刻比较（TIMESTAMP）；两者语义不同，不能都按日期算 |
| 停滞用 `updated_at` 而不是 `created_at` | “doing 停滞”关注最后一次动作；每次状态/内容变化都会刷新 |
| 三桶分别返回 + `urgentCount` 去重 | 同一任务可能既逾期又停滞；分桶便于 UI 分组，去重保证“紧急 N 项”不虚高 |
| 客户端时区头一律忽略 | 共享空间的业务日必须对所有成员一致（需求 R06） |
| 每桶 limit 20 | 首屏聚焦，完整列表由任务接口分页提供 |
